# Contributing to NDX

Thank you for considering a contribution.

## Project status

NDX is experimental. The current v0.1 model is a working proposal, not a stable or published standard. Please keep proposals, implemented behavior, and future plans clearly distinguished.

## Before opening a pull request

- Search existing issues and pull requests for related work.
- For format changes, explain the problem, alternatives, compatibility impact, and security implications.
- Keep pull requests focused and describe how the change was tested.
- Add or update tests and examples when behavior or the data model changes.
- Do not add confidential, personal, copyrighted, or proprietary documents as fixtures unless you have permission and a clear license.
- Never add executable scripts or active content to example documents.

## Changes to the format

Changes affecting document meaning, security, accessibility, or interoperability should include:
1. A concise rationale.
2. At least one positive example.
3. Negative or malformed examples where relevant.
4. Compatibility and migration considerations.
5. Tests demonstrating the intended behavior.

## Security reports

Please do not publish exploitable vulnerability details in a public issue. Use GitHub's private vulnerability reporting if it is enabled for this repository. If private reporting is unavailable, contact the maintainers privately through the NDX Foundation organization.

## Conduct

Be respectful, constructive, evidence-based, and welcoming. Critique technical ideas and implementations, not people.
